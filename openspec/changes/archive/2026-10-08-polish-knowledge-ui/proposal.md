# 提案：polish-knowledge-ui（知识页观看效果优化）

## 为什么

迭代 2 把检索/问答/溯源做出来时，KnowledgePage 全部用的内联样式和硬编码颜色，
「能看」但没到迭代 1 材料页的水准，且有**深色模式真缺陷**：

- 回原文弹层用了 `var(--fg, #111)` —— `--fg` 变量不存在（实际叫 `--text`），
  深色模式下弹层文字回退成近黑 `#111` 配深底 `--bg`，基本不可读；
- 命中卡与答案框硬编码 `border: 1px solid #d0d0d0`，深色主题下边框糊掉；
- `<mark>` 高亮 `#ffe58a` 配 `#111` 为硬编码，未走主题变量。

检索与问答是本产品的核心体验面，这套原始呈现会让溯源（R3.3 的卖点）看起来像调试输出。

## 改什么

纯前端呈现层，两个文件：`frontend/src/pages/KnowledgePage.tsx` + `frontend/src/styles.css`。

1. 深色模式三处缺陷修复（弹层文字变量、硬编码边框、硬编码 mark 色）。
2. KnowledgePage 内联样式全部迁入 styles.css 语义类（`kn-` 前缀），全走既有 token。
3. 命中卡呈现升级：score 分值条（tabular-nums）、查询词客户端高亮、八字段溯源排版。
4. 检索/问答的加载、空、错误三态：skeleton 占位、「思考中」动画、无命中引导文案。
5. 回原文弹层升级：品牌化头部、ESC 关闭、主题化高亮。

## Non-goals

- **不加依赖**：不引 UI 框架、不引动画库（skeleton/动画纯 CSS）。
- **不改任何行为契约**：不新增/修改 API 字段，不动 `scripts/` 下任何验证脚本的断言数
  （browser-verify 的选择器全在登录/首页/材料页，知识页重构互不影响——已核对）。
- **不做引用点击跳转**：[n] 出处 chips 只做样式与悬浮提示；点击回原文仍只从命中卡进入。
  真要做属于行为变更，需 spec delta，不混进视觉变更。
- **不动登录页/材料页/首页**：迭代 1 的呈现已达标。
- **不新增路由/状态库/全局重构**。

## 为什么没有 specs delta

本变更不改任何 Requirement / Scenario 的行为契约：R3.3 溯源闭环（点击命中 → 回原文高亮）
的交互原样保留，只是变好看。四件套里的 specs/ 在此为空是刻意的，不是遗漏。

## 与活动变更的关系（纪律说明）

AGENTS 约定「同一时刻只有一个活动 change」。当前已有两个活动变更
（add-class-scoped-retrieval、add-token-auth），本变更是用户指示下起的第三个。
依赖顺序：**本变更的实施排在 add-class-scoped-retrieval 归档之后**
（共享 reset/额度解锁流程，避免验收脚本计数基线混叠）；提案先行落档不受影响。

## 验收口径

- `npm run build`（tsc）零错误；
- browser-verify 19/19、verify-all 各脚本计数与既有基线**完全一致**（本变更不引入新断言）；
- 深浅两套主题下人工核对：命中卡、弹层可读性、高亮可见性，截图留证。
