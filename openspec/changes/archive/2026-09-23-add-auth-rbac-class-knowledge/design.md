# Design: add-auth-rbac-class-knowledge

- 关联变更：`openspec/changes/add-auth-rbac-class-knowledge/`
- 迭代：CampusClaw 迭代 1

## 技术栈决议

**采用**：Go（标准库 `net/http`，不引 web 框架）+ bcrypt + 服务端 Session Cookie；MySQL 8.0；前端 React 18 + TypeScript + Vite（原生 CSS，`react-markdown` + remark-gfm）；入口 Nginx（托管静态资源 + 反代 `/api`、`/health`）；Docker Compose 三服务。

**交付链路**：浏览器 → Nginx → Go → MySQL。**信任边界落在 Go**。前端不直连 DB；`db` 不映射宿主端口；上传目录不做静态暴露。

### 与第 2 课样板的冲突及处理

第 2 课课件样板终稿把 `design.md` 写成 **Flask + SQLite**（备选 Node + Express）；第 3 课课件样板迭代 1 用 **Go + net/http + MySQL**，并把 Flask + SQLite 列为被否决的备选。课件对这类不一致给了明文处理方式：

> 「可行，但当前需求是前后端分离。**若第 2 课 design 已写成单体，先改规约或按 design 实现并写清差异。**」
> 「**技术栈若与第 2 课 design 不一致，先改规约再实现。**」

**本仓选择：走 delta 改规约，采用 Go + MySQL。理由**：

1. 本迭代已经确定前后端分离（Nginx 反代 + SPA），Flask 单体样板与这个形态不一致；
2. 第 4 课要做检索，需要多连接与全文索引，SQLite 单写者模型会成为阻碍；
3. 第 3 课课件把 Go + MySQL 作为本迭代参考栈，判定语料（核对总表）也以它为准，采用它可以让「规约—实现—验收」三者同源。

**否决备选**：

| 备选 | 否决理由 |
|---|---|
| Flask + SQLite（第 2 课样板） | 与前后端分离形态不一致；SQLite 在后续检索与并发连接上是负债 |
| Node + Express | 可行，但课件样板与判定语料均以 Go 为准，换语言会让核对总表的「代码搜什么」一列全部失效 |
| Go + ORM（GORM） | 可用，但本迭代的核心验收点是「隔离条件显式可见」。ORM 的隐式全局过滤器容易让隔离条件藏起来，不作为默认选择 |

## Decisions

### D1 会话承载的字段

**决议**：会话至少可判定 `user_id`、`role`、`class_id` 三项。

**理由**：认证只回答「你是谁」；授权与隔离要靠角色与班级。缺任一项，后续的授权与隔离需求**不可判定**。

会话 ID 是**不透明随机串**，放在 `HttpOnly` Cookie 里。

**备选与否决**：
- 把 `role` / `class_id` 放进 Cookie 或 localStorage —— 否决。客户端可改，等于把授权判定权交给调用方。
- 会话只存 `user_id`，用时再查库取角色与班级 —— **采用**。角色与班级每次从用户表读取，不采信任何客户端回传值。

### D2 租户（班级）的来源

**决议**：`class_id` **只取自服务端会话 / 用户表**。请求里的 query、Header、表单中的 `class_id` **一律忽略**。

**理由**：采信请求中的班级，等于把隔离判定权交给调用方；这是水平越权（BOLA/IDOR）的标准成因。

**验收方式（反证）**：上传时在表单里塞 `class_id=<另一班>`，落库仍须归会话所在班级。

### D3 跨班返回 403 还是 404

**决议**：**404**，且与「记录不存在」返回**完全同形**（同状态码、同响应体结构、无标题/正文/存储路径泄漏）。此约定写进 `README.md`，全文一致。

**理由**：403 会泄露「该资源存在但你不该看」，便于攻击者遍历扫描 ID。404 让「存在但跨班」与「不存在」不可区分，从响应上关闭枚举信道；排障改走服务端审计日志。

**备选**：403 + 明确文案 —— 否决，理由是上面的存在性泄露。若产品日后需要向用户解释「无权访问」，必须先有资源级审计与告警，属另一组规约。

### D4 按 ID 取行的路径设计

**决议**：列表与按 ID 取行是**两条独立路径**。
- 列表：`WHERE class_id = <会话班级>`，在 SQL 层过滤；
- 按 ID：**不在 SQL 里提前过滤班级**，先取行，再在 Go 里核对 `class_id`（fetch-then-check）。

**理由**：若按 ID 也在 SQL 里过滤掉跨班记录，跨班访问会返回空结果，无法与「资源不存在」区分，也就无法统一返回同形 404。

### D5 上传的事务边界与失败清理

**决议**：`materials` 与 `knowledge_entries` 写入**同一事务**；尽量把校验放在写盘之前；若入库失败，删除已落盘的文件。

**理由**：只写盘不入库 → 第 4 课检索没有数据；只入库不写盘 → 下载必然失败。两种半成品都会污染验收。

### D6 认证方案：服务端会话 Cookie，不用 JWT

**决议**：签发服务端会话，会话行存 `sessions` 表；Cookie 属性 `HttpOnly` + `SameSite=Lax`；**本机 HTTP 环境不加 `Secure`**（加了浏览器会拒绝写入）。

**理由**：本迭代是浏览器同源站点，不是开放 API 或移动端。服务端会话的登出可**立即失效**（删行即可），而 JWT 在过期前难以作废。且 `role` / `class_id` 不进入客户端载荷。

**备选**：JWT / Bearer —— 否决，理由见 `proposal.md` 的 Non-goals。`SameSite=None; Secure` —— 否决，本课同源，Lax 足够。argon2 —— 可选，本迭代用 bcrypt（**禁止 MD5/SHA 无盐哈希**）。

### D7 配置与启动：缺配置即失败，不落默认值

**决议**：`SESSION_SECRET`、数据库凭据、上传目录与上限、会话 TTL、预置账号口令、登录失败阈值**全部来自环境变量**。任一必填项缺失时**启动失败并退出**，**禁止静默落到内置默认值**。

**理由**：内置默认密钥等于把会话标识的签发权交给任何人。

**备选**：内置开发默认密钥（克隆即可跑）—— 否决，第三方复现必须显式填写 `SESSION_SECRET`。

### D8 存储名由服务端生成

**决议**：上传文件的**磁盘存储名由服务端生成**（随机串 + 白名单扩展名）；客户端文件名**只作展示标题**，不参与任何路径构造。

**理由**：防路径穿越（`../`）。扩展名用**白名单**（`.txt` / `.md`）而非黑名单——黑名单无法穷举。

### D9 `/health` 的存活语义

**决议**：`/health` **不查库**，只判进程存活；DB 不可用时**业务接口返回 503**。

**理由**：把「存活」与「就绪」混在一个端点，DB 短暂抖动会被编排系统误判为容器故障并重启容器，反而放大故障。

### D10 登录失败与限流

**决议**：账号不存在、口令错误、**被限流**三类响应**同形**（同状态码、同响应体、等价耗时）。用户不存在时也执行一次**等价耗时的哈希比较**。对用户名 + IP 组合做失败限流。

**理由**：三者可区分即可用来探测账号存在性。

**明确不用 429**：429 会暴露「该账号正处于锁定状态」，本身就是账号枚举的依据。锁定期内即使口令正确也拒绝，响应仍与凭据错误一致。

### D11 会话固定（session fixation）防御

**决议**：登录成功**必须换发新会话 ID**，并作废登录前的会话。

**理由**：否则攻击者可诱使受害者使用一个已知的会话 ID，待其登录后共用同一会话。
