# 01 · 目录与分层规范

> 常驻约束。与 `AGENTS.md` 同级效力，改代码前先读。
> 判定方式：违反任一条即为不合规，不因"人手少""只是临时写一下"豁免。

## 1. 分层与依赖方向

依赖只允许**自上而下**，箭头方向即 import 方向：

```
cmd/server（装配：读配置 → 建连接池 → 建处理器 → 挂路由 → 起服务）
        ↓
internal/<领域>（业务：auth / materials / knowledge / conversation / skills / agents / prompt / prompttpl / mcp）
        ↓
internal/db · internal/config · internal/obslog（基础设施：连接池、配置、日志）
```

- **入口层不得含业务判断**。`cmd/server/main.go` 只做三件事：装配、注册路由、声明中间件顺序。
  一旦里面出现 `if role == "teacher"` 这类判断，就说明该判断应该下沉到 `internal/` 或中间件。
- **领域层不得 import 另一个领域的处理器包去做 HTTP 调用**。领域之间要协作，传的是**函数或数据**，
  不是 HTTP 请求：`conversation` 调 `knowledge.ChatClient`，不是 `http.Post` 到自己的 `/api/ask`。
- **基础设施层不得 import 领域层**。`internal/db` 不认识"技能"这个词；`internal/obslog` 不认识 HTTP。
- **禁止循环依赖**。Go 编译器会拦住，但设计时就该避免——不要靠"拆一个 util 包"来绕。

自查（在 `backend/` 下执行）：

```bash
go list -f '{{.ImportPath}} -> {{join .Imports " "}}' ./... | grep campusclaw
```

看到 `internal/db -> internal/materials` 这类反向边即为违规。

## 2. 外部依赖放在最外侧

| 外部依赖 | 唯一的落点 | 不得出现的位置 |
|---|---|---|
| MySQL | `internal/db`（建池/建表/种子）+ 各领域包里的 `*sql.DB` 用法 | 领域之外不得出现裸 `sql.Open` |
| Qdrant | `internal/knowledge/qdrant.go` | 其它包 |
| LLM / 嵌入网关 | `internal/knowledge/ask.go`、`chatstream.go`、`toolcall.go` | 其它包 |
| MCP 服务器 | `internal/mcp/client.go` | 其它包 |
| 环境变量 | `internal/config` | **其它任何地方**（见 §4 与安全规范 §3） |

需要换掉某个外部依赖时，改一个文件即可——这是这条规范的可验收形态：
**如果换 Qdrant 要改三个包，说明分层已经破了。**

## 3. 模块命名

- 包名 = 目录名，**小写、单数、无下划线**（`prompttpl` 而不是 `prompt_templates`）。
- 文件名按职责切分，不用 `utils.go` / `helpers.go` / `common.go` 这类无主语的名字。本仓现有的合法例子：
  `ask.go`（一次性问答）、`chatstream.go`（流式会话）、`toolcall.go`（带工具的一轮调用）、
  `tools.go`（工具解析与执行循环）。
- 一个文件超过 500 行或出现两类不相关职责时拆分。当前最大的领域文件是
  `internal/conversation/conversation.go`（会话编排），已按"编排 / 流式线格式 / 工具循环"拆成三个文件。

## 4. 新增功能落在哪一层

按顺序判断，**取第一个成立的**：

| 要加的东西 | 落在 |
|---|---|
| 新的业务能力（材料、技能、模板、工具…） | `internal/<新领域>/`，一个目录一个能力 |
| 已有能力的新接口 | 已有领域包内新增 `Handler` + `cmd/server/main.go` 注册一行路由 |
| 横切关注点（认证、限流、请求标识、日志、CORS） | 中间件，注册在 `main.go` 的路由外层 |
| 与外部系统对接的新协议 | 领域包内的 `client.go`，**不新增顶层目录** |
| 前端新页面 | `frontend/src/pages/`，页面里不直接 `fetch` |
| 前端可复用的界面块 | `frontend/src/components/`，属性只进不出（不读全局状态） |

**不允许**出现的两个位置：

- `internal/util/`、`internal/common/`、`internal/shared/` —— 无主语的包是分层破口的起点。
  确有共享逻辑时，它应该属于某个具体领域，或下沉到基础设施（如 `obslog`）。
- 根目录新增 `xxx.go` —— 根目录只有文档与子目录。

## 5. 本仓的结构基线（2026-10-27 实况）

```
backend/
  cmd/server/main.go        装配与路由表（唯一注册路由的地方）
  internal/config           唯一读环境变量的地方
  internal/db               连接池 / 建表 / 幂等种子
  internal/auth             登录、JWT、refresh 轮换、RequireSession / RequireTeacher
  internal/materials        材料列表 / 详情 / 下载 / 上传
  internal/knowledge        切片、嵌入、Qdrant、混合检索、问答、流式会话、工具调用轮
  internal/conversation     会话编排：取会话→取应用→路由技能→检索→组消息→调模型→落库
  internal/skills           技能文件解析与 CRUD
  internal/agents           智能体 CRUD 与关联写入
  internal/prompt           班级提示词（一班一条，兜底）
  internal/prompttpl        提示词模板库与 {{变量}} 渲染
  internal/mcp              MCP 服务器管理、JSON-RPC 客户端、工具解析与执行、审计
  internal/obslog           一行一条 JSON 日志与请求标识
frontend/src/api.ts         前端访问后端的唯一出口
frontend/src/pages          页面（工作台 / 材料 / 知识检索 / 解题助手 / 登录）
frontend/src/components     组件（对话 / 配置 / MCP 面板 / 上传对话框 / 命令面板 / 提示）
mcp-server/                 独立进程的示范 MCP 服务器（自己的 go.mod，不 import backend）
deploy/                     docker compose（api / mysql / qdrant / nginx）
scripts/                    验收脚本（verify-all 等）
docs/                       手册、报告、证据、规范
openspec/                   规约（specs 为真相源，changes 为进行中的变更）
```
