# 03 · 测试规范

> 常驻约束。**"能跑"不算通过，退出码为 0 才算。** 报告里的"预期"列是硬判定。

## 1. 目录与命名

| 类型 | 位置 | 命名 |
|---|---|---|
| 后端单元/集成测试 | 与被测文件同包，`xxx_test.go` | `Test<被测函数>_<场景>` |
| 后端端到端（进程内，连真库） | `backend/cmd/e2e/` | `go run ./cmd/e2e`，汇总打印 `N/N` |
| 接口级回归（黑盒 HTTP） | `apitest/`（Python） | 专项用例 `METHOD__专题.py`（如 `POST__routing.py`） |
| 前端界面端到端 | `scripts/e2e-ui.mjs` | 每个场景一个 `check('名字', fn)` |
| 验收总入口 | `scripts/verify-all.sh` | 一条命令跑完并把日志落到 `.verify-logs/` |

**为什么专项用例要 `METHOD__专题.py` 这种命名**：runner 按文件名末段推方法名，
写成 `routing.py` 会被推成非法方法名 `ROUTING` 而整体崩掉。这是踩过的坑，不是风格偏好。

## 2. 用例按三类组织

每一条能力至少三类各一条，缺一类视为覆盖不足：

1. **正常路径**：合法输入 → 期望的成功结果（不只看状态码，要看落库结果）。
2. **失败路径**：未登录（401）、角色不足（403）、跨班/不存在（404）、参数非法（400）、
   依赖不可用（502/503）。**每条都要断言"没有产生副作用"**——失败请求不应留下半条记录。
3. **边界**：长度上限与上限+1、0 条与 1 条、空串与纯空白、并发同键（唯一约束）。

数值必须写具体：不写"大量数据"，写"200 条"；不写"较快"，写"≤ 3 秒"。

## 3. 测试数据隔离

- `scripts/verify-all.sh` 按序插入 `reset-demo-data.sh`：**每轮从同一初始状态出发**。
- 跑完用 `bash scripts/reset-demo-data.sh --yes` 复位；不复位就再跑一次会因唯一约束失败，
  那不是产品缺陷，是测试没做隔离。
- 用例之间不得依赖执行顺序。需要共享前置（如"先有一个智能体"）时，在用例内自己创建，
  不要指望上一个用例留下。
- 测试产生的文件写进仓库内相对路径（`storage/`、`docs/evidence/`），**不用 `/tmp`**——
  在 Windows 原生 curl 下 `/dev/null` 与 MSYS `/tmp` 都不可用。

## 4. 一键运行的命令与报告位置

```bash
# 后端：字体检查 + 单元/集成
cd backend && go vet ./... && go test ./...

# 全链路验收（会自己插复位脚本）
bash scripts/verify-all.sh

# 接口层黑盒回归（生成 HTML 报告）
cd apitest && python run_all.py

# 前端界面
node scripts/e2e-ui.mjs
```

| 产物 | 位置 |
|---|---|
| 验收日志 | `.verify-logs/`（每次一个带时间戳的文件） |
| 接口回归 HTML 报告 | `apitest/report-*.html`（不入库，`.gitignore` 已排除） |
| 运行证据（报文、SSE、审计） | `docs/evidence/`（**入库**，用于回答"到底传了什么"） |

**判定只看退出码**：`0` 通过、`1` 断言失败、`2` 运行环境不满足（如库未启动）。
看到 `2` 不要去改断言，先修环境。

## 5. 断言纪律

- **不只断言状态码**。凡是有落库的接口，要回表核对：
  `SELECT count(*) FROM skills WHERE class_id=?` 必须真的多了一条。
- **断言要能失败**。写完一条用例，故意破坏实现跑一次，确认它变红；一直绿的用例通常是空断言。
- **改断言必须同步改预期计数**。`verify-all.sh` 里 `run` 调用的预期值（如 `41/41`）是硬编码的，
  改了用例数量却忘改预期，会让脚本永远失败或永远通过。
- 涉及 SSE 的断言：**不能用 `requests.iter_lines(decode_unicode=True)`**，它会截断长 `data:` 行；
  必须自己 `iter_content` 按字节分帧再显式 UTF-8 解码。

## 6. 新增接口的最低要求

每个新接口合入前至少三条用例：

1. 正常调用返回预期结构（含关键字段值，不只状态码）；
2. 身份/角色不满足 → 401 或 403，且**未落库**；
3. 边界（超长 / 空 / 不存在 / 跨班）→ 400 或 404，且错误体是 `{"error": "..."}` 形态。

失败的用例保持 `[ ]`，**不得标记完成**（`AGENTS.md`：失败项不带入下一项）。
