# 02 · 前后端开发规范

> 常驻约束。前端指 `frontend/`，后端指 `backend/`。与本文件冲突的写法一律以本文件为准。

## 一、前端

### 1.1 目录与组件约定

| 位置 | 放什么 | 不放什么 |
|---|---|---|
| `src/pages/` | 一个导航项对应一个页面（工作台 / 材料 / 知识检索 / 解题助手 / 登录） | 可复用界面块 |
| `src/components/` | 跨页面复用的界面块与模态 | 直接调 `fetch` 的代码 |
| `src/api.ts` | **访问后端的唯一出口** | 界面逻辑 |
| `src/styles.css` | 全部样式 | 组件内新增 `<style>` |

- 文件命名：组件 `PascalCase.tsx`（`McpPanel.tsx`），非组件模块 `camelCase.ts`。
- 组件属性只进不出：组件不读 `localStorage`、不读全局变量，需要的数据靠 props 传，
  需要改变外部状态靠回调。
- 一个组件文件超过 450 行必须拆分。当前最长的 `TutorConfig.tsx` 已把 MCP 部分拆成
  `McpPanel.tsx`（第 7 课补齐项）。

### 1.2 接口调用的统一入口

**页面与组件不得直接 `fetch`。** 所有请求写在 `src/api.ts` 的具名函数里，理由是可验证的：

- 401 的**静默刷新**（用 refresh 换 access 再重放原请求）只在 `api.ts` 实现一次；
  逃出这个出口的请求拿不到它，用户会在 token 到期时被动退出登录。
- 错误码到中文提示的映射（`describeApiError`）同理，逃出去的请求只能显示 `HTTP 500`。

唯一例外：`uploadMaterial` 用 `XMLHttpRequest` —— 因为 fetch 无法报告**上传进度**。

### 1.3 加载 / 错误 / 空状态

每个异步界面三态齐全，缺一不可：

| 状态 | 要求 |
|---|---|
| 加载中 | 显示"正在载入…"之类的文本，不得留白；**不得显示"还没有数据"**（那是把加载中说成空） |
| 出错 | 显示可读原因。**403 不得显示成"请重新登录"**，404 不得显示成"网络错误"——错误语义不能被改写 |
| 空 | 说清"接下来该做什么"，不是"暂无数据"。例：`还没有技能。至少建一条「解题引导」类技能。` |

表单提交按钮：请求在飞时禁用并改文案（`保存中…`），避免双击产生两条记录。

### 1.4 命名与格式

- React 组件 `PascalCase`；函数与变量 `camelCase`；类型与接口 `PascalCase`；常量 `UPPER_SNAKE_CASE`。
- CSS 类名 `kebab-case`，沿用已有前缀分段：`.tt-*`（解题助手）、`.kn-*`（知识检索）、`.mcp-*`（工具面板）。
- **禁止内联 `style`**。一次性显隐也写成类（如 `.file-input-hidden`）——
  内联样式绕过主题变量，深色模式下必然与其它元素不一致。
- 缩进 2 空格；字符串用单引号；不用分号结尾（与现有文件保持一致，由 `tsc` 兜底类型）。
- 提交前 `npm run typecheck` 必须 0 错误。

## 二、后端

### 2.1 接口命名

- 路径一律 `/api/<资源复数>`，资源名小写、复数、连字符分词：`/api/mcp/servers`、`/api/prompt-templates`。
- 方法语义固定：`GET` 读、`POST` 创建或执行动作、`PUT` 整体更新、`DELETE` 删除。
  **不用 `PATCH` 做局部更新**——本仓的"局部"都用 `PUT` + 显式字段判断（见 MCP 的 `auth_token` 三态）。
- 资源 id 走路径参数：`/api/skills/{id}`。**不接受 `?id=`**。
- 动作子资源放末尾：`/api/mcp/servers/{id}/connect`、`/api/prompt-templates/{id}/render`。

### 2.2 请求与响应结构

- 全部 **`snake_case`**，不混用 camelCase（前端 `api.ts` 的接口类型与之一一对应）。
- 列表响应必须带**计数或范围说明**：`{"materials": [...], "count": 3, "class_id": 1}`；
  空的列表回 `[]` 而不是 `null`（Go 侧用 `make([]T, 0)`，不是 `var x []T`）。
- 创建成功回 `201` + 完整对象；删除成功回 `204` 无响应体。
- **令牌类字段只进不出**：`auth_token` 入库后任何响应都不得回显，只回 `has_auth: true`。

### 2.3 错误码与错误信息格式

统一结构，两个键：

```json
{ "error": "bad_request", "detail": "同名技能已存在" }
```

`error` 是**机器码**（前端据此翻译），`detail` 是给人看的补充（可为空）。

| `error` | 状态码 | 用于 |
|---|---|---|
| `unauthorized` | 401 | 未带凭证 / access 过期 / refresh 无效 |
| `forbidden` | 403 | 已登录但角色不足（学生调教师接口） |
| `not_found` | 404 | 不存在**或跨班**（两者必须同形，不得泄露"存在但不属于你"） |
| `bad_request` | 400 | 参数缺失、超长、枚举非法、文件类型不支持 |
| `db_unavailable` | 503 | 数据库不可用（靠 `requireDB` 中间件统一拦） |
| `mcp_unreachable` | 502 | 上游 MCP 服务器连不上 / 返回非法 |

`error` 的值**不得**包含动态内容（不得出现 `"技能 12 不存在"` 这样的码）——动态内容放 `detail`。

### 2.4 参数校验的位置

| 校验类型 | 位置 | 例子 |
|---|---|---|
| 形状与长度（必填、≤N 字、枚举） | handler 入口，解码后立即判 | 技能文件 8000 字上限、模板名 64 字 |
| 身份与角色 | 中间件 `RequireSession` / `RequireTeacher` | 学生调 `POST /api/skills` → 403 |
| **资源归属（班级）** | 领域层，**fetch-then-check** | `WHERE id=? AND class_id=?`，取不到回 404 |
| 班级来源 | **只取服务端会话** `sess.ClassID` | 请求体/query/header 里的 `class_id` 一律忽略 |

参数校验一律**先校验再落库**，不许"先写进去再改"。解析失败必须回 `400` 且**不产生任何副作用**。

### 2.5 分页与排序

- 列表参数名固定为 `limit`（`offset` 目前未使用，需要时再加）。
- `limit` 默认 50、上限 200；越界或非法值**回落到默认**而不是报错（日志接口不该因为参数脏就失败）。
- 排序必须在 SQL 里显式写 `ORDER BY`，不依赖 InnoDB 的自然顺序。
  现有约定：主数据按 `id ASC`（稳定），审计类按 `id DESC`（最新在前）。

### 2.6 Go 代码约定

- 只用标准库 + `go-sql-driver/mysql`（+ `golang.org/x/crypto` 用于口令哈希）。
  **不引入 Web 框架、日志框架、ORM**。新增依赖需要在 change 的 `design.md` 里写明理由。
- `gofmt` 必须干净；`go vet ./...` 必须 0 输出。
- 错误处理：`fmt.Errorf("...: %w", err)` 保留链路；对外的错误码不用 `err.Error()` 拼装。
- 并发：共享状态用 `sync.Mutex` 保护；`http.Client` 全局复用，不每次新建。
