# 04 · 安全规范

> 常驻约束，优先级高于"先把功能做出来"。下列任一条被违反，都算不可合入。

## 1. 默认拒绝，逐资源判权

- **默认拒绝**：新增接口默认需要 `RequireSession`；需要教师的再套 `RequireTeacher`。
  除 `/health`、`/api/login`、`/api/refresh` 外，**没有"默认放行"的接口**。
- **逐资源判权**：拿到 id 之后必须再核对归属，不能只靠"列表里查不到"。
  标准写法是 **fetch-then-check**：`WHERE id=? AND class_id=?`，取不到直接 `404`。
- **跨班与不存在必须同形**：都是 `404` + `{"error":"not_found"}`，响应体不得包含标题、正文、
  上传者、磁盘路径中的任何一项。任何能被用来"探测某条记录是否存在"的差异都是越权通道。
- **前端隐藏入口不构成访问控制**。界面按角色隐藏按钮只降低可发现性；
  服务端必须独立判定，学生手工构造请求同样得到 `403`。

红线实例（本仓已实现，不得回退）：

| 场景 | 期望 |
|---|---|
| 学生 `POST /api/skills` | 403，且库中无新增行 |
| 2 班教师读 1 班材料详情 | 404，响应体与"不存在"逐字相同 |
| 请求体里塞 `class_id: 2` | 忽略，仍按会话班级处理 |
| 学生 `GET /api/mcp/tool-calls` | 200，但只返回本班记录（不是 403 —— 读权限班级内共享） |

## 2. 密钥只从环境变量读

- 密钥来源唯一：`internal/config`（后端）、启动时注入的环境变量（前端构建不注入任何密钥）。
- **缺失即启动失败，不落默认值**。`config.Load()` 里不允许出现 `|| "changeme"` 这类兜底。
- `.env` **只在本机存在**，入库的只有 `.env.example`（**只写键名不写值**）。
- **在仓库里搜不到任何密钥真值**。提交前自查：

```bash
git grep -nEi 'password|secret|api_key|token' -- ':!*.md' ':!.env.example' | grep -v '\$\|os.Getenv\|env\['
```

- **令牌类字段只进不出**：MCP 的 `auth_token` 存库后任何响应都不回显，只回 `has_auth`。
  更新接口的"不传 = 保留、传空串 = 清空"必须是显式三态，不能用"空串等于不改"含混过去。

## 3. 密钥不进日志

- 日志里**不得出现**：口令、access/refresh token、`auth_token`、上传文件正文、
  检索到的材料正文、用户提问原文（query 参数）。
- 访问日志只记**路径**不记 query。`POST /api/search?q=...` 的 query 就是用户的提问，
  落进日志等于把提问复制一份到日志系统。
- `obslog` 刻意不提供"整个结构体打印"的能力——要记什么必须手写字段名，
  这样误记敏感字段需要一次显式动作，不会被一句 `log.Printf("%+v", req)` 顺手带出去。

## 4. 输入校验与输出转义

- **校验在主侧（服务端）**。前端校验只为体验，服务端必须再校验一遍：长度、枚举、类型、
  文件大小与扩展名（只收 `.txt` / `.md` / `.skill.md`，按扩展名 + UTF-8 可解码双重判定）。
- **磁盘存储名由服务端生成**，客户端文件名只做展示标题，**不参与路径构造**。这是防目录穿越的
  结构性做法，比过滤 `../` 可靠。
- **输出转义**：前端渲染模型回答与材料正文时走 `markdown-it`，**必须关闭 HTML 直通**
  （`html: false`），否则材料里的一段 `<script>` 就成了注入载荷。
- **不可信内容不进系统消息**：检索到的资料只能作为数据进用户消息一侧。
  系统消息只放角色提示词、技能说明与边界句——否则一段材料正文就有机会下达指令。
- 外部工具返回的内容同样视为不可信：它进的是 `role: "tool"` 消息，不是系统消息。

## 5. 依赖漏洞检查的频率

| 触发点 | 动作 |
|---|---|
| 每次新增/升级依赖 | `cd backend && go list -m -u all`；`cd frontend && npm audit --omit=dev` |
| 每次迭代验收前 | 上述两条各跑一次，结果写进该轮 `docs/` 的验收记录 |
| 严重漏洞（Critical / High） | 当轮必须处理：升级、替换或写明为什么暂不能升（记入 change 的 `design.md`） |

本仓的依赖面刻意很小（后端仅标准库 + MySQL 驱动 + `x/crypto`），
**新增依赖需要理由**：在 `design.md` 里写清"不加它会多付什么代价"。

## 6. 其它不得回退的约定

- `/health` **不查库**：它只回答"进程活着"，回答不了就去查库会让 DB 抖动被误判成进程故障。
- **口令哈希用 bcrypt**，不得出现明文或可比对的弱哈希。
- **登录失败限流**：同一账号连续失败达阈值后锁定一段时间（`auth.NewLimiter`），
  错误响应不得区分"账号不存在"与"口令错误"。
- **CORS 与代理边界**：Qdrant 与两类模型网关不对客户端暴露，密钥只在服务端；
  浏览器只与 Nginx / 本进程通信。
